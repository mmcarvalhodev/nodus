## [Unreleased]

### Added — Fase 2 (Runtime Dinâmico)
- **Runtime genérico de seletores** (`engines/runtime.js`, 992 linhas) — substitui os 7 engines hardcoded (chatgpt/claude/gemini/grok/perplexity/copilot/deepseek) por um interpretador único de specs declarativas JSON. Strategies suportadas: `scanBack`, `closestParent`, `prevInList`, `prevSibling`, `prevSiblingWalk`. Novo contrato via `chrome.runtime.sendMessage({type:'get_selectors', platform})` → background devolve `{ok, spec, version, source}` com fallback cascade (histórico local → fetch fresh → null).
- **Sistema de specs remoto** no `background.js` — 8 funções novas (`getInstallId`, `buildAuthHeaders`, `registerInstall`, `fetchSpecs`, `checkSpecVersion`, `saveSpecToHistory`, `getSpecForPlatform`, `initSpecSystem`). Autenticação HMAC-SHA256 (`X-Nodus-Install/Sig/TS/Runtime/License`), idempotência no `/register`, cache local em `chrome.storage.local` (máx 5 versões), refresh periódico via `chrome.alarms` a cada 6h. Worker de produção: `https://nodus-worker.mmcarvalho-dev.workers.dev`.
- **Fallback bundled** (`engines/specs_bundled.json`) — spec inicial v1.0.0 com 7 plataformas usada quando o histórico local está vazio e o worker está offline.
- **Instrumentação Health doc 07** no runtime — helpers `reportRuntimeHealth(category, event, extras)` + `withHealth(category, event, fn)` (preserva sync/async, detecta null em category `detection` e re-throws em todas). 10 funções críticas envolvidas: `init`, `shouldShowButtons` (infrastructure), `getQuestion`, `getAnswerText`, `getIdeaData`, `startObserver` (detection), `injectButtons` (ui), `handleQuickSave`, `handleAutoCapture`, `handlePaste` (interaction). Eventos postados via `chrome.runtime.sendMessage({type:'report_runtime_health', payload})`; background buffera em `chrome.storage.local` (`nodus_runtime_health_buffer`, ring máx 200 eventos). POST ao `/health` no nodus-worker será ativado quando a rota estiver disponível.
- **Sanity Checks passivos** (`health/health_sanity_checks.js`) — 4 checks spec-derivados read-only, complementam o `withHealth` reativo detectando estado quebrado antes de manifestar como falha funcional: `spec_answer_container_has_matches`, `spec_input_present`, `spec_observer_target_present`, `spec_button_injected`. Exposto em `window.NodusSanityChecks.run(spec)`. Carregado como content script estático no ISOLATED world (ao lado de `health_bridge.js`).
- **Sanity Scheduler** no runtime — trigger reativo: MutationObserver dispara `maybeRunSanityChecks()` ao fim de cada callback; debounce 3s + cooldown 60s entre runs para limitar volume em páginas ativas. Baseline agendado 3s após `observer.observe()` iniciar. Falhas reportadas individualmente via `reportRuntimeHealth('sanity', check_name + '_failed', {trigger_reason, details})`.
- **Exposição pública do runtime** — `window.NodusRuntime` com getters vivos (`spec`, `specVersion`, `platformName`, `runtimeVersion`) + método `runSanityChecks()` que retorna o result (também dispara reporting). Permite inspeção ad-hoc via DevTools e consumo pelo painel Diagnostic do dashboard.
- **Painel Diagnostic no dashboard** — nova aba 🩺 (4ª posição, após Projetos) com visibilidade em tempo real: info da spec ativa (version/source/platform), install info, sanity checks com botão "Run Now", ring buffer de health events (últimos 50 em tabela), counters por categoria na última hora, ações Refresh/Clear Buffer. Auto-refresh a 5s do buffer enquanto visível, self-stop ao trocar de aba. Módulo novo: `content/modules/dashboard_diagnostic.js`, registrado como content script ISOLATED.
- Permissão `alarms` em `manifest.json`, host_permission para `nodus-worker.mmcarvalho-dev.workers.dev` e `nodus-specs.mmcarvalho-dev.workers.dev`.
- `engines/runtime.js` e `engines/specs_bundled.json` em `web_accessible_resources`.
- **Telemetria de opt-out** — novos event types `telemetry_disabled` e `telemetry_enabled_event` (`telemetry.config.js`) + método `trackTelemetryToggle(enabled, source)` (`telemetry.tracker.js`) que faz **flush imediato** (bypassa min_events/timer) — captura o último ping ANTES da flag de telemetria ser persistida, senão o opt-out viraria fantasma. Toggles em `popup.js` e `dashboard_modal.js` emitem `telemetry_toggle {enabled, source}` ANTES de gravar a flag; handler em `background.js` chama o tracker. Permite métrica "% de usuários que desliga telemetria" via D1 (`by_event.telemetry_disabled`). Privacidade: payload é só `{source: 'popup'|'dashboard', new_state}` — zero texto/ID. Validado live: batch chegou ao D1 com `telemetry_disabled:{count:1}`.

The previous pass still matched the assistant reply's `⋮` menu (`aria-label="Mostrar mais opções"`, `data-test-id="more-menu-button"`) instead of the input's `+` button, and the menu-item regex matched stray text inside the reply's body (e.g. "Aperta o botão 📎 Enviar arquivo"). Diagnostic dumps now report buttons within the input container and items inside open menu panels.
- Gemini chain drop — **reveal-input-via-MAIN-world-monkey-patch**. Logs from the image-drag pattern showed `File inputs found: 0` on Gemini: unlike ChatGPT/Claude, Gemini doesn't mount `<input type="file">` on page load — it only renders after the user clicks `+` → `Enviar arquivos`, and that menu item also calls `input.click()` which opens the OS file picker. The patched click tags the target input with `data-nodus-revealed="1"` and returns early so the OS picker never opens. The isolated-world drop handler, after its initial `input[type="file"]` search fails on Gemini, awaits `_revealGeminiFileInput()` (postMessage round-trip with 3s safety timeout) then queries the revealed input by the data attribute (fallback: first visible/any `input[type="file"]`). Once found, it fills via `DataTransfer` + dispatches `change`/`input` as for every other platform. End result on Gemini: drag the chain chip → drop anywhere near the input → brief menu flash (∼450 ms) → file attached, same as manual `+`-picker selection.
- Gemini chain drop — **pivot to the image-drag pattern** after logs proved Chrome strips `Files`/`DownloadURL` from `DataTransfer` on extension-initiated drags. Console at dragstart showed `types: ["downloadurl","Files"]` + `files.length: 1` (both isolated + MAIN-world); at drop the same `DataTransfer` was reduced to `types: ["text/plain"]` + `files: 0`. This is a Chrome security behaviour — only OS-level drags (downloads bar, file explorer) preserve `File` data across the full drag lifecycle. Consequence: Gemini's native dropzone cannot be triggered from JS, period. The isolated-world call creates its own `blob:` URL (now tracked by a `let isolatedBlobUrl` that `close()` revokes alongside `blobUrl`), calls `setData('DownloadURL', 'text/markdown:' + filename + ':' + blobUrl)`, and logs the resulting `types` array. The MAIN-world bridge still runs the real `items.add(_file)` in capture phase so that `dataTransfer.files[0]` is a real `File` at drop time.
- Gemini chain bridge — more verbose diagnostics in `chains_drag_bridge.js`: logs `_file` / `_blobUrl` state when the chip `dragstart` is caught, logs `types` and `files.length` at the end of the MAIN-world handler, and adds a global `drop` capture observer that reports what Gemini actually saw (`target.tagName`, `types`, `files.length`). Also guards the chip-walk at 10 parent steps to avoid accidental infinite loops and logs `location.origin` at load so we can spot the rare case where `postMessage` doesn't reach the bridge due to origin drift.
- Gemini chain-as-file — **removed the auto-click `+` path entirely for Gemini** and locked the flow to native drag-and-drop. Panel helper text updated: "O Gemini vai reconhecer como arquivo e mostrar a área de drop — solte ali." The user now drags the chip → Gemini's own "Solte os arquivos aqui" overlay activates → drop attaches the `.md` via Gemini's native file handler.
